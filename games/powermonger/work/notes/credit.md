# Powermonger release credit (PMCredit): `patches/pm_credit.s`

Tags: **[obs]** observed in Hatari 2.6.1 (1 MB STE TOS 1.62, plain ST TOS 1.04, GEMDOS HD folder); **[disasm]** read from a RAM dump with `tools/m68dis.py`.
Requirement (user): every release shows a small, discreet `v<VERSION> enhanced by dad_prg` so archivists know which version they are playing. Small text, a palette colour already on that screen (palette untouched), never over anything meaningful.

* **Version**: ONE place, the `TXT:` line at the end of `patches/pm_credit.s` (`dc.b "v1.0 enhanced by dad_prg"`; the renderer pads/centres to whole 16-px words by itself, so a longer version still centres, up to 20 words). `tools/package.sh` reads it with `sed -n 's/^TXT:.*"v\([^ ]*\) enhanced by dad_prg".*/\1/p' patches/pm_credit.s` for the zip names and the READMEs (PMPack was told). Start version **1.0**. (vasm 2.0f here has no `equs`, so a string constant is not possible; the `TXT:` line is the constant.)
* **Screen** = the main menu (Welcome to the World of PowerMonger / START NEW CONQUEST / CONTINUE CONQUEST / PLAY RANDOM LAND / LOAD DATA DISK). [obs] It is a 119-row window (screen rows 40..158, x 112..207) on an all-black 320x200 screen: rows 160..199 are black in both buffers (`work/credit_base.bin`). The credit goes in the bottom 6 rows 194..199, 16-px word columns 7..12 (24 characters = 96 px, centred).
* **Loop** [disasm]: `$13e0c..$13e52`: both buffers cleared once (`$12cc6`, flip `$187a`, `$12cc6`), then per pass `jsr $1870` (wait VBL), `jsr $7a56` (draws the open windows into `[$2df7c]` from the table `$7a36`), `jsr $7202` (pointer), flip, until `$2df6e != 0`. The screen is NOT cleared per pass, the windows are redrawn over themselves. [obs] breakpoints on the menu: `$13e24` hit, `$cf12`, `$13d82`, `$130ce`, `$12cc6` not hit (they are other users of `$7a56`: the `$cee6` window loop, the in-game loop). The menu window is built by `$bf58` (`$7b10` copies the window description `$bfda` to the instance buffer `$7bac`, `$a91a` fills it with the player's name); the type word `$7a3c` = `$e`.
* **Hook**: `jsr $7a56` at `$13e24` (6 B `4eb900007a56` -> `4eb9000cdb00`); blob `$CDB00..$CDBA3` (164 B incl. the 24-byte string) in the `pm_` range, after pm_tooltip's blob (`$CD000..$CDA48`) and before its data (`$CDC00..$CDFFF`). The hook calls the original `$7a56`, then draws iff `[$7a36] != 0` and the long at `$7bc8` is `"Welc"` (the first characters of the menu's text in its instance buffer). The draw is idempotent (stores the 6 words per row), so redrawing every pass into whichever buffer is the back buffer fills both within two passes.
* **Font**: the game's 4x6 font at `$8976` (tooltip.md section 3): block `ch>>2` of 48 B (6 rows x 4 planes x 1 word), column `ch&3` of the 16-px word. Colour 1 is the glyph background, 2..5 the ink, so ink = plane1|plane2|plane3; the mask is written in one colour (`COLOUR equ 2` = palette index 2 = `$332`, Hatari renders (102,102,68); the window background is index 1 `$221` (68,68,34), the window text is cream (204,204,170)). Palette read from `$ff8240` in the menu: `000 221 332 443 554 665 321 431 520 541 661 451 341 231 023 234`. The mask loses the glyph's antialias shades (flat colour).
