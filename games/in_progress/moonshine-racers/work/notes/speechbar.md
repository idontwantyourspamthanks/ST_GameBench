## 0. One page (read this first)
* **What it is.** The message text (2 lines, the game's own 8x8 font, white with a grey shadow) and the talking face (a 16x24 half-size copy of the game's face sprites) are drawn into a permanent black strip, rows **16-41 (26 rows)**, directly under the top bar. The sky keeps rows **42-64 (23 rows)**; the stock message box used rows 16-64 (49 rows). Mockups: section 1.
* **Draw on change, per buffer.** Every piece (a character, the face frame, the wipe at the end of a message) is drawn into a buffer only when THAT buffer lacks it (shadow per buffer at `$B2A00`/`$B2A10`), so no flags, no "twice" logic; it works unchanged in the extra frames.
* **The ticker's state machine (`$11ef0`, `$11ab/$11b1/$11b2/$11a2/$11a8`) and the face state machine/RNG (`$f90c`) run exactly as stock.** Only the drawing is replaced: `sb_glyph` (`$120a4` -> `rts`), `sb_erase` (`$12086` -> `rts`), `sb_face` (`$f994`: draw the frame), `sb_bar` (`$f90c`: entry hook, draws the text, wipes the strip at the message end).
* Sections 2-6: mechanism, cost, gates, extras, what is NOT identical. Numbers are filled in section 3 as the runs finish.

## 1. Layout (mockups for approval)
Pixel-exact 320x200 mockups, 3x nearest-neighbour, made from the REAL shipped-HUD frames `work/hud/build/shots/{drv,drvsp,gno,gsp}` (rows 16-64 cleared to the sky exactly as `hd_stage` paints them, then the strip drawn by `sbart.py` with the game's own font and face sprites):
`work/speechbar/mock_typing.png` (message typing, 31 of 49 characters), `mock_held.png` (held, 2 lines), `mock_long.png` (the longest game message: 4 stock lines -> 2 strip lines), `mock_short.png`, `mock_idle.png` (no message: empty strip), `mock_standing.png` (time-out state, held),
`mock_before_after.png` (the shipped default on top, the strip below), `mock_faces.png` (all 22 face frames: half size (x6) above the full-size original (x2)).
Geometry: strip rows 16-41, black = palette colour 2 (same as the bar, so the bar and the strip read as one); text at x 8..303 (37 columns, 2 lines at rows 20-27 and 30-37), body = colour 14 (white, `hd_stage` already sets palette A colour 14 to `$777` every pass), shadow = colour 4 (`$333`);
face 16x24 at x 304-319, rows 17-40 (one 16-pixel group: 8 bytes per row). Face scaling: every 2x2 block with at least 2 opaque pixels -> the palette-A colour nearest to the mean RGB of its opaque pixels (best of the three tried: majority, darkest, mean-nearest).
Text wrap: greedy word wrap at 37 columns, a `$0d` counts as a space (all 57 message records of the game fit in 2 lines; `mock.py` prints `messages 57 overflowing 0`). The stock text had up to 4 lines of 20 columns.
Visible consequences (the user's decision): (1) the strip is permanent: **26 sky rows are gone** whether a message is shown or not (the idle strip is empty black); (2) the face is half size (the mouth moves 5-8 pixel rows at that size); (3) the text is white/grey instead of cream/dark; (4) the typed text is wrapped differently (fewer, longer lines); (5) a message is never drawn over the sky or the mountains.

## 2. Mechanism (what runs where)
Hooks (all `default: no`; `list`/`verify` ALL OK with the private tool and, at the end, with `tools/msrpatch.py`):
| patch | site | original -> new | what |
|---|---|---|---|
| `sb_bar` | `$f90c` (start of the face routine, called right after the ticker `$11ef0` in `hd_stage`'s `newhud` AND in `mx_sync`'s `hud:` list) | `2a781008 7000` (`movea.l $1008.w,a5 / moveq #0,d0`) -> `jmp $B6040.l` | `sbent`: shows the current ticker state in the buffer being drawn (text, wipe) and continues in the stock face routine at `$f912` (the two displaced instructions replayed) |
| `sb_face` | `$f994` (`lea $1b076.l,a0`, the sprite draw inside the face routine, reached with d0 = this pass's sprite index) | `41f90001b076` -> `jmp $B6600.l` | draws the 16x24 face frame into the strip (only when this buffer shows another frame, and only the rows that differ); returns as the stock `rts` |
| `sb_facestat` (option, VISIBLE) | `$f994` | same | one frame per message and buffer (frame of the first pass): the mouth does not move |
| `sb_glyph` | `$120a4` (the ticker's per-character glyph draw, 2 callers inside `$11ef0`) | `2a781008` -> `rts` | no per-character draw in the sky |
| `sb_erase` | `$12086` (the 49-row message-box restore, 2 callers/fall-through inside `$11ef0`) | `7070` -> `rts` | no box restore |
Requires `hd_stage hd_init hd_clouds`; conflicts `ta_face ta_facestat ta_glyph ta_erase ta_init mr_map mr_digit tb_blit*` (the first four are replaced by the new drawing, `ta_init` requires `ta_erase`, so the speech-bar set uses `hd_init` (same site `$edea`, clears hd_stage's `painted` flags) instead; `mr_map mr_digit tb_blit*` only overlap the blob addresses; they are dead/optional patches).
The set that was measured (`sblib.py`, `S`): `hd_clouds hd_nomap hd_nomap2 hd_stage mr_edge rd_draw rd_geom rd_init ta_ymw tb_car tb_carph tc_* hd_init sb_bar sb_face sb_glyph sb_erase` (= the default minus `ta_face ta_glyph ta_erase ta_init`, plus `hd_init` and `sb_*`); with the pacer `+ mt_clock mt_pre mx_pre mx_sync`. `hd_nomap`/`hd_nomap2` (occupancy-map writers inside the old drawing paths) become dead code, harmless.

State (data `$B2A00-$B2E3F`, zero at start): per buffer a shadow of 8 used bytes (`$B2A00` for `$70000`, `$B2A10` for `$78000`): `+0` message drawn (low word of the record address `$11a8`, 0 = none), `+2` characters drawn, `+4` face frame drawn (sprite index `$21-$36`, 0 = none), `+6` dirty text lines (bit 0/1). Shared layout state `$B2A20`: message, characters laid out, column, line offset, at-word-start flag; `$B2A40`: 256 longs, one per character of the message = glyph strip offset << 16 | byte offset of the glyph cell in the buffer (0 = nothing to draw: space, `$0d`, overflow, a character outside `$20-$7a`).
What `sbent` does each pass (a5 = the back buffer):
1. **Sentinel**: `cmpi.l #$0000ffff,2560(a5)` = planes 0 and 1 of the first word of strip row 16. It is `$0000ffff` in the black strip (colour 2 = plane 1 only), `$ffffffff` after `hd_stage` painted the sky over rows 16-64 (race start/restart, first pass into each buffer) and `$00000000` after a screen clear: anything else and the strip (26 rows x 160 B, about 9.6 k cycles) is refilled black and this buffer's shadow cleared. No hook at the race init is needed.
2. **Idle** (`$11ab == 0`): if this buffer's shadow still shows something (message or face) the dirty text lines (8 rows x 152 bytes each, `movem.l` of 10 registers) and the face box (24 rows x 8 bytes) are filled with the strip pattern once, shadow cleared. Otherwise exit: **154 cycles** [M] (stage part `sbent` of a no-speech pass, `res/stage2_race_start_S.json`).
3. **Active** (`$11ab != 0`): message M = `$11a8` (low word of the record address; the text starts 4 bytes behind: x, y, colour, hold), characters typed so far n = `$11a4 - M - 4` (`$11a4` = low word of the ticker's text pointer `$11a2`, which the stock ticker advances one character per pass and which stops at the terminator during the hold). If this buffer shows (M, n) already: exit. Else: extend the shared layout (greedy word wrap at 37 columns, `$0d` = space, one cell per character; incremental, one character per pass while typing), draw the characters this buffer lacks (BN .. n-1: 2 per typing pass, one new and the one of the previous pass that went into the other buffer, exactly the stock pattern) with 8 `movep.l` per glyph (the strips are pre-composed: plane bytes 0, ~shadow, body|shadow, body), mark the dirty lines, store (M, n). A different message in this buffer (stale shadow) wipes its lines first.
4. then the stock face routine runs (`$f912`..): its state machine and RNG are untouched; at `$f994` `sb_face` draws the frame if this buffer shows another one: the 22 face frames are `$B4460`/`$B5A00` (192 B each, 4 planes x 24 rows), a table of the rows that differ between neighbouring frames (22 x 7 words at `$B6498`, after the 22 face pointers at `$B6440`) limits the copy to the mouth rows (5-8 of 24 for the 0<->1 transitions).
The ticker is called BEFORE `$f90c` (in `newhud` and in the extras' `hud:`), so `sbent` always sees the state of this pass.
Register contract: the stock face path (its sprite kernel at `$15e82`: `movem.w (a1)+,d1-d4/a0/a2/a4/a6`) clobbers d0-d7, a0-a4, a6; every caller of `$f90c` (`newhud`, `mx_sync`'s `hud:`) must therefore not rely on anything but a5 = `$1008`, which `sbent` keeps. The new code uses only those registers and saves nothing (an earlier build saved 12 registers: -212 cycles per active pass by dropping it).
Why there is no flicker (also in the extra frames, two screen buffers `$70000`/`$78000`): the picture of a buffer after `sbent` is a pure function of (ticker state at that instant); what a buffer shows is tracked by ITS shadow, not by flags; the extras restore the ticker state after their own early ticker step (`mx_sync` `hud:`: saved/restored `$1198-$11b3`+`$10f8`) BEFORE `$f90c` is called, so the extra frame shows the state of the main frame that precedes it (n), the next main frame shows n+1: the displayed sequence is monotone (character counts never decrease within a message, the erase is a state change `$11ab -> 0` that both buffers see in order). The stock extras showed the next character one frame early; the strip does not. Proof: section 5.

**Typing pass overhead 2.9 k (< 3 k target met), held pass 0.5 k, the 2 erase passes of a message 7.4 k each** (solid fill of the used text lines, 8 rows x 152 B each, plus the face box, once per buffer). Inside a typing pass `sbent` takes 1.7 k (`prof_sb.py`): entry/checks 413, layout of one character 351, two glyph draws (8 `movep.l` each, one new character and the one the other buffer lacks) 784, rest 130; the face hook 0.5 k average; the stock ticker (0.42 k) and the stock face state machine (0.4 k) must keep running as stock. **Extras per tick (the user's metric)**, race_drive, 130 s emulated, 8 MHz, tick on, zig steering, extras on (`ext_summary.py`, `res/ext_X_8.json` vs `ext_XS_8.json`; X = default set, XS = speech bar): ticks with one extra picture **26.6 % -> 27.9 %** (349 -> 365 extras in 1,312 ticks), displayed fps about +0.2. Speech ticks 24.7 % -> 26.4 %, no-speech ticks 34.1 % -> 33.7 % (noise). So the speech bar alone moves the STE from ~12.9 to ~13.1 displayed fps; **it does not get near 20 fps**: the `ta_*` patches had already taken the speech overhead from 19.7 k to 8.4 k per typing pass, the speech bar takes the rest to 2.9 k, a tenth of the 0.3-0.4 VBL per render that is needed.

## 6. Exactly what differs on screen from the default set (VISIBLE, `default: no`)
Rows 0-15 and 65-199: identical in every frame (A, B0). Rows 16-41 (26 rows, whole width): a permanent black strip carrying the message and the face (F: sky gradient, or the message). Rows 42-64 (23 rows): always sky in S; in F they carry text lines 3-4 and the lower half of the 32x48 face while a message is shown: the differing pixels are only inside x 112-303 (text 112-271, face 272-303), 700-800 px per speech frame on average (74 % of the emulator frames have a stock message box). Other differences: text wrapped into 2 lines of 37 columns, white/grey instead of cream/dark, face 16x24, 4-line messages need no scrolling. Timing: a character appears in the same pass as in stock; in extra frames the stock showed the next character one frame early, the strip does not. At a race restart the game paints sky into the displayed buffer; F shows rows 16-41 as sky for a pass there, S now repaints the displayed buffer's strip black at once (see section 7).

## 7. Restart glitch: found, fixed
The Hatari race_drive gate showed one frame at the restart (pass 1707 -> 0) in which a buffer's strip differed from the model. Per-pass log (`res/old4`, `drive_other.py`): at the restart the game paints sky (colour 15) into the DISPLAYED buffer (its `hd_stage` `painted` flag is 0 and its strip was all colour 15 for that pass; the default set shows the same sky there). The shadows were consistent; the sentinel is pixel based, so a missed shadow flag was not the cause; the displayed buffer was only repaired one pass later, when the game next drew into it. Fix: when the repaint path runs for the drawn buffer, it also tests the other buffer's sentinel and repaints it and clears its shadow. My first version of that fix reused `d0` (a pattern register) for the buffer address and wrote garbage (1,560 px of colours 0-2); fixed with `d6`; the final-build gates above ran on that build. Sentinel: `cmpi.l #$0000ffff` (planes 0 and 1) also catches a cleared screen.
Unrelated: one earlier race_up pair of captures was not synchronised between F and S (rows 65-199 differed, i.e. different game state: Hatari input timing); the rerun is IDENTICAL.

## 8. Not proven / risks
Hatari/Unicorn only; no real hardware (`movep` is 68000-68030). The hook assumes every caller of `$f90c` is the stage list (`hd_stage newhud`, `mx_sync`; `mf_sync`/`mg_sync` of the other agents call the ticker and then `$f90c` the same way, not run with them). Messages needing more than 2 wrapped lines would clip (none of the 58 records does). The face is a 2x2 mean-colour reduction; the mouth moves a few pixel rows, `sb_facestat` removes that and is 0.33 k cheaper per typing pass (5,581 vs 5,912 stage cycles) [M]. Floppy boot of the set not run.
