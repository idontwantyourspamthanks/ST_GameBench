## Classification of every FAIL in logs4
* `ed2_straight_ste2m` (full script) and `q2_straight_ste`: `IndexError` in ed2.py (`sel[3]` in `run_script`; the quick script's `barhere` candidate list `[...][1]` on a 3-segment straight). Script limits, confirmed by the traceback; quick script fixed (candidate list guarded), rerun `q4_straight_ste` = ALL PASS. The full 88-edit script is not defined for a straight track (it needs >= 4 selectable segments) and was not run there.
* `ed2_stock_ste2m` (first run): `vPlay 0`, race of campaign pos 0, `$102c = 0`: the check ran `wait_race(press=True)`, which presses SPACE every 3rd poll and clicks the shop EXIT; a SPACE at a start screen starts a new game from the title (= track 0). Evidence: the later run without key presses races pos 3 (`ed2_q_mste2m`: `pos=3 ptr=0x113820`), and `play3b_edit`: ptr inside the edited block. `ed2_stock_ste2m_b`: no key presses, but `race_up()` requires `$100e > 30`, which was not true on the edited road (`$100e = 2` at race start in `play3b_edit`) so the race was never "seen" in 120 s although it ran (screenshot `play3_edit_s012s.png`: the edited road, `$5ff8 = 406` after 10 s); criterion changed to `$23c0 != 0 and $1024 == 0`.
* `vPlay 0` / `V_START 0` FAILs: the editor hands `vPlay` to the menu, which consumes it and `V_START` at once; the gate read them after the fact (log line `vPlay 0 V_START 3` once, `V_START 0` the next read). Check replaced by the race's campaign position and stream pointer.
* Curve-ring FAILs (`ed2_q_mste2m`, `ed2_q_st2m`, `ed2_stock_ste2m`): ring `[1638, 1637 ..]` vs expected zeros, sampled with `$5ff8 = 167 / 69` and `$1024 = 1` (the car had already moved; the ring is the window at the car position, not at unit 0), and the game's ring values are not `expand_curve` values (no offset 0..299 of `expand_curve` equals that ring: searched). In `ed2_stock_ste2m` the sample WAS at unit 0 (ring all 0 == expected all 0) and failed only on the `any(got)` clause (edits start at unit 128, so the first 32 entries are zeros). So the ring test as written cannot prove anything non-trivial; it was dropped. Evidence that the race uses the edited road instead: ptr inside the edited block and the screenshots / ring contrast in `play3b_*` (edited ring -356..-294 at `$5ff8 = 334` vs stock 0 at the standing start), pos == 3 in the 4-track runs. This is a gate-design error, not shown to be a product fault.
* `play3` (first two runs): `boot_editor` hard-coded 3 tracks; fixed (item 4 = TRACK EDITOR always). `play3_edit` run 1: same `$100e > 30` criterion.
* "Bus/Address error lines: 3": printed by every run including the stock v1.1 flows (`welcome.py` on v1.1 build); not investigated further.
