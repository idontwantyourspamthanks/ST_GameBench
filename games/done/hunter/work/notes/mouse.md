# Hunter mouse pointer: "a bit jerky" on the menu (Hatari STE/Mega STE/TT) - causes, fix `ptr_*`, gates (HunterMouse)

Tags: **[obs]** measured here (tool `tools/huntmouse.py`, logs `/tmp/hunmouse/ev_*.json`, Hatari 2.6.1 + the fork source `/home/ryan/Code/hatari-pist/src`); **[disasm]** `tools/m68dis.py` on `/tmp/jerk/live_menu2/ram.bin` (a live TT menu dump) and capstone on the Amiga `main`; **[src]** Hatari source; **[INFERENCE]** unproven.

## 0. Verdict
1. The jerk is real and has **three game-side causes**, all in the pointer path `$aff4 -> $b01e -> $b290 -> $b30e/$b32c -> $d8/$da(a5) -> $c69a -> $a65c`:
   - **A. Packets land in VBLs by luck.** The game moves the pointer at once, per packet, and redraws once per VBL. Hatari sends one mouse packet per IKBD "auto-send" tick, `Keyboard.AutoSendCycles = 150000` 8 MHz cycles = **53.3 Hz** [src `ikbd.c:621`], against a 50 Hz VBL. Per 16 VBLs the pointer sees `1 1 1 ... 0 2`: one VBL where it **stops**, the next where it **jumps double** (about every 0.3 s). Packets per VBL on the STE, 150 consecutive VBLs: `1211011111111101211111111111012111111111111012111011111110121...` [obs]. At a 60 Hz refresh (forced `$ff820a`) 39 % of the VBLs have no packet at all (section 3). On the TT the pattern is less regular (`0 1 2 0 1 0 1`).
   - **B. One packet is split across two VBLs.** The X byte and the Y byte of a packet are decoded 1.28 ms (10,240 cycles) apart, so a VBL boundary falls between them for **7 % of the packets** (21 of 294 STE, 21 of 296 Mega STE, 20 of 265 TT): the pointer's path bends (a diagonal moves in X one VBL and in Y the next).
   - **C. Only negative deltas are halved.** `$b30e`/`$b32c`: `ext.w d0 / bpl.b +2 / asr.w #1,d0`. Left and up run at 2/3 of the speed of right and down (`asr` rounds toward -inf: -3 -> -2, -1 -> -1). Measured at 3 px/VBL input: right/down **3.00**, left/up **2.00** px per VBL [obs]. The Amiga version's mouse code has **no halving at all** (section 5).
2. Excluded with numbers (section 4): the erase/draw racing the beam (the draw ends at line 12; the picture starts at line 63), ACIA overrun or dropped/merged packets (no OVRN, sums conserved exactly), the VBL handler blocking the ACIA (it takes 7 k cycles), our p4_ikbd/sky/tb patches (PP's original code and v1.2 give the same numbers), flips (the menu has none).
3. **Fix** (`ptr_vbl`, `ptr_x`, `ptr_y`, `default: yes`, 182 B of code + 18 B state, window `ptr_` `$8DA3A-$8DBEF`): the packet handlers only *collect* the packet (both axes together, no halving); once per VBL, just before the redraw, the pointer moves by the mean of the last three VBLs' collected motion, remainder carried (exact). Measured 50 Hz STE at 3 px/VBL: zero-VBLs 5/75 -> **0/75**, double steps 5 -> **0**, sd 1.10 -> 0.55, left = right = 3.0 px/VBL (was 2.0).
4. All gates passed (section 7): `verify` and `verify --floppy` ALL OK; huntab pixel-IDENTICAL on 7 snapshots (negative control MISMATCH); the Python model of the algorithm equals every drawn position (0 of 370 differ; the carry-less variant fails); the pointer moves exactly the raw-packet sum (variant with halving and variant without carry FAIL); cold boots to the 3D view with the menu clicks and an item-table hover + click on **ST, STE, Mega STE, TT (HD), STE, TT, Falcon (floppy)**.

## 1. The code [disasm]
- VBL handler `$c5f0 -> $c63a -> ... -> $c69a: tst.b $1ce(a5) / bmi.w $a65c`: with bit 7 set the pointer is redrawn **every VBL** on the shown page. `$a65c` reads the base from `$ff8201/$ff8203`, position `$d8/$da(a5)` (x 0..`$e4`=312, y 0..`$e6`=191 in the menu), erases the saved background `$a6cc`, saves the new one and draws (`$a6ee`).
- IKBD path: `$afde` (vector `$118`) -> `jmp $1ae` (PP's hook: `move.b $fc02.w,d0`, F9 test, `jmp $aff4`) -> `$b01e`: a header `$f6..$ff` starts a packet (state table `$b00a`, length table `$b014`); the bytes then go through `$b290`: state 3 = mouse (`$f8..$fb`): header (buttons), X byte -> `$b30e`, Y byte -> `$b32c` (the packet's last byte). State 5 = joystick packet `$fd` (the reply to the `moveq #$16` poll of every VBL; p4_ikbd sends it without the 350 us wait).
- Each of `$b30e`/`$b32c`: `ext.w d0 / bpl.b +2 / asr.w #1,d0 / add.w $d8(a5),d0 / bpl / clr.w d0 / cmp.w $e4(a5),d0 / blt / move.w $e4(a5),d0 / move.w d0,$d8(a5)`.
- `$d8/$da` are read only by the pointer draw (`$a65c`), the hit tests (`$a566`, `$adbe`, `$aae0`) and written by the game itself at screen changes (`$a224`/`$a24a` +-`$30`, `$a274` = 2, `$24f6` +2). They are not used for steering: the pointer is a pure UI cursor.

## 2. Method [obs]
- **Host mouse.** `xdotool` sleeps are too loose (events 8-14 ms apart), so `tools/huntmouse.py` compiles a 25-line XTest injector: relative events at exact 10 ms spacing (`mm DISPLAY 10000 dx dy n ...`). 3 host px per 10 ms = 150 ST px/s = **3 px per 50 Hz VBL** (the Hatari window shows ST px at 2x and divides `dx` by 2 with a carried remainder [src `main.c:520`]). Scenarios `mid` (3 px/10 ms), `fast` (6 px/10 ms), `cons` (a path that never touches the clamp).
- **Per-VBL log without disturbing timing.** Two scratch-free `test_` patches (`patches/test_mlogd.s` at `$a65c`, `test_mlogb.s` at `$1b8`, both `hdonly`, `default: no`, not in the release set) write 8-byte entries into free RAM `$B8200` (HD builds): the pointer position the game DRAWS each VBL (type 0) and every byte the ACIA handler decodes (type 3, stamped with the VBL count). The packets are re-assembled offline, so the same loggers serve PP's code, v1.2 and the fix. After the run `savebin` dumps the log. Earlier I also logged with Hatari breakpoints (`b pc=$a65c :trace :file`): identical picture, but 100 VBL took 134 s and the host events no longer matched emulated time, so the final numbers use the in-RAM log.
- Variants (`huntmouse.py build_variant`): `orig` = no patch but the staging code (PP's pointer code), `before` = v1.2 default set without `ptr_*`, `after` = with. Statistics per run of same-direction motion, 3 VBLs trimmed at each end, clamped VBLs dropped.
- **Hatari delivers host motion only in steps of >= 3 host px per 10 ms** [obs: 1/2/3/4/6 px at 10 and 5 ms: 1 and 2 px steps produced no packets at all, 3 px@5 ms none, 3 px@10 ms and 6 px@5-10 ms all; the X pointer did move (xdotool getmouselocation)]. That is Hatari/SDL, not the game; so very slow motion could not be measured (`slow2` scenarios in my scratch runs gave 0 packets). The numbers below are therefore for "normal" speeds (150 and 300 ST px/s).

## 4. Excluded [obs]
- **Erase/draw racing the beam.** Breakpoints at `$a65c` and its `rts` `$a6ca`, 50 draws (STE) / 34 (TT): the VBL handler runs at FrameCycles 124-148, the draw starts at **952-972** and ends **5,180 cycles** later (STE: 6,136-6,148, line 12 of 313; TT: 888-896 to 3,136-3,146, 2,248 cycles). The picture starts at line 63 (cycle 32,256). No tearing, no flicker. The erase and draw are one routine; nothing is visible between them.
- **ACIA drops/merging.** Status byte at `$afe6` over 100 VBL at 8 px/10 ms (a heavier stream than the gates use): always `$83` (IRQ, TDRE, RDRF), never bit 5 (OVRN). Bytes arrive 10,240 cycles apart, three per packet, and the VBL handler is short (`$c5f0` .. `$c626` = 6,456-6,960 cycles). `cons` (section 7): the pointer moved exactly the sum of the raw packets (23,8 vs 23,8) in the fixed build, so no motion is lost anywhere between the ACIA and `$d8/$da`. The two packet streams (joystick reply + mouse) share the serial line: the mouse packet is queued behind the 3-byte joystick reply (X byte at about 73-76 k cycles), which only shifts the phase.
- **p4_ikbd (no 350 us wait in the joystick poll) and the v1.2 VBL/ACIA hooks (`sky_vbl`, `sky2_aciax`, `tb_vbl`).** PP's code (`orig`) shows the same pattern and the same halving as v1.2; the host-event timing noise between runs (zero-VBLs 7-13 of 75) is larger than any difference.
- **Pointer drawn on the shown page while the game flips.** In the menu there are no flips (`/tmp/jerk/live_menu2/report.txt`: "flips in 150 VBL: 0"); the pointer is drawn and erased on the same page. The in-game pointer vanishing for one VBL per frame (jerk.md section 1) is a different effect of the 3D loop's page copies and not part of this fix.
- **Hatari's delivery.** `Main_HandleMouseMotion` keeps the remainder of the 2x window scaling, `IKBD_SendRelMousePacket` sums everything (no loss; packets > 127 are split). The cadence (section 0 A) and the >= 3 px/10 ms threshold above are Hatari's; the game can only make its own pointer immune to the cadence.

## 5. The Amiga version [disasm]
`alt/amiga/Hunter (Activision).adf`, file `main` (track 2, 14 tracks; `tools/amiga_extract.read_file`), offset `$bf7c`: `move.w $a(a6),d4` (JOY0DAT), `sub.w d1,d0 / ext.w d0 / neg.w d0 / add.w $de(a5),d0 / bpl / clr.w d0 / cmp.w $ea(a5),d0 / blt / move.w $ea(a5),d0 / move.w d0,$de(a5)` and the same for Y. The counter difference is added **unscaled in both directions**: no halving. So the ST code's halving of the negative direction is a port artefact and the intended feel is 1 count = 1 pixel, as on the Amiga and as the ST/GEM desktop. The Hatari window also relies on it ("the ST mouse cursor stays in sync with the host mouse", `main.c:520`).

## 6. The fix
Files: `patches/ptr_vbl.s` (site `$c69a`, 8 B `tst.b $1ce(a5) / bmi.w $a65c` -> `jsr $8da70.l / nop`; blob `$8DA70` 144 B; state `$8DBC0` 18 B), `ptr_x.s` (site `$b30e` -> `jmp $8da40.l`, 10 B blob), `ptr_y.s` (site `$b32c` -> `jmp $8da50.l`, 28 B blob), `huntpatch.py` (`PREFIX_RANGES["ptr_"] = ($8DA3A, $8DBEF)`), `patches/README.md` (map rows, blob ends, section), PATCHES.TXT / FLOPPY.TXT / FLOPPY2.TXT (new column and a bullet).
- `ptr_x` (X byte): `ext.w d0 / move.w d0,TX` (no halving).
- `ptr_y` (Y byte, the packet's last): `ext.w d0 / add.w d0,PY / move.w TX,d0 / add.w d0,PX / clr.w TX`. Each add is one read-modify-write instruction; the ACIA handler (IPL 6) cannot be interrupted by the VBL (IPL 4), so both axes of a packet always arrive in the same VBL (cause B).
- `ptr_vbl` (once per VBL, before the redraw): if PX, PY and both filters are zero it does nothing but the original two instructions (150 cycles). Otherwise per axis: `u = PX; PX -= u` (the packets since the last VBL), `S = u + h1 + h2 + f`, `step = S div 3` truncated toward 0 (`divs #3`), `f = S rem 3`, `h2 = h1; h1 = u`; if `step != 0`: `pos = clamp(pos + step, 0, $e4/$e6)` with the game's own clamp code. Then `tst.b $1ce(a5) / bpl / jsr $a65c` as before.
- Why a 3-VBL box with a carried remainder: a stall `0` and the double `2` are adjacent or one VBL apart, so a 3-tap mean puts them back; the carry makes the filter exact: `sum(step) = sum(raw) - f_final/3` with `f_final` a multiple of 3 below 3 in magnitude, i.e. **after three still VBLs the pointer has moved exactly the raw sum**. Simulation over the logged packets of the `before` runs (sd of px/VBL, mean over STE/Mega STE/TT runs): raw 1.26, [1 2 1] 0.75, EMA/2 0.60, **box3 0.51**, [1 2 2 1] 0.51, box4 0.45, EMA/3 0.35 (but an EMA leaves up to k-1 pixels undelivered after a stop). On the `after` logs at 50 Hz STE box4 gives 0.38 against 0.52 for box3 (at 60 Hz about the same), for 10 ms more lag; box3 was kept (less lag; stall and double are gone already).
- Cost: one VBL hook of about 150 cycles when idle (huntab: +0.13 % of the work cycles per 15-VBL frame), a few hundred while the mouse moves (two `divs`). Latency: the pointer lags the mouse by one VBL and stops two VBLs after it.
- Behaviour kept: position variables, limits, hit tests (they see the position that is drawn), click handling, the pointer sprite code, the in-game pointer. Changed on purpose: left and up are now as fast as right and down (right/down unchanged). The clamp is applied only when the step is non-zero (the game clamped on every packet, including zero ones; its own `$da` +-`$30` excursions are therefore left alone between motions).

## 7. Gates [obs]
- `huntpatch.py verify` and `verify --floppy`: **ALL OK** (`ptr_vbl` / `ptr_x` / `ptr_y` sites match the HD and floppy tail dumps; `test_mlog*` are `hdonly`). `build`, `build --floppy`, `build --floppy --two-disk` and `doc patches/PATCHES.TXT` run with the new default set (no site-table or window overflow).
- **Pixel-identical (huntab)** `--only ptr_vbl ptr_x ptr_y --lock --flips 1 6 --points 2 --vbls 300`, 1 MB snapshots foot_stand/foot_walk/car_stand/car_drive/car_turn/hills_stand and 4 MB foot_stand: **ALL IDENTICAL** (visible bytes of both pages, first patched frame and 6 flips later, 15 VBL/frame in both runs); work cycles +0.13 % (+1,340...+3,060 cycles per ~15 VBL). **Negative control**: the same set with `eori.b #$ff,$26c00.l / eori.b #$ff,$2e700.l` added to the hook (a byte flipped in both pages) -> `DIFFER` on every snapshot, `MISMATCH`, exit 1; a variant with an unbalanced stack kills the game (no frames, huntab aborts).
- **Algorithm model** `huntmouse.py model`: the Python version of `ptr_vbl` fed with the logged ACIA packets must give every drawn position: `after_ste_mid` 370 VBLs 0 differ, `after_st_mid` 370/0, `after_ste_cons` 310/0, `after_ste_mid60` (60 Hz) 444/0. Negative controls: `broken` (remainder dropped) 3 differ of 309 -> FAIL; `before` (halving, direct) 125-149 differ -> FAIL.
- **Conservation** `huntmouse.py cons` (scenario `cons`, never touches the clamp): `after`: pointer moved (23,8), raw packets sum (23,8) -> OK; `before`: moved (92,58) vs raw (28,15) -> FAIL (the halving); `broken`: (12,15) vs (13,15) -> FAIL.
- **Cold boots to the 3D view** (`huntmouse.py cold`; boot clicks hit Start / Action / name / mission; then the item table is opened with the pointer, four cells hovered (`$252` = cell index at the pointer) and a click on cell 4 makes weapon 4 current (`$212`), then the table is closed): **OK** on ST (TOS 1.04, 1 MB, HD), STE (1.62, 1 MB, HD and floppy), Mega STE (2.06, 4 MB, HD), TT (3.06, 4 MB, HD and floppy), Falcon (4.04, 4 MB, floppy). `MARKER` `HNPO`, sites `$c69a = 4eb90008da704e71`, `$b30e = 4ef90008da40`, `$b32c = 4ef90008da50` on all. **Negative control** `cold --variant nox` (X motion never committed): see section 8.
- Per-VBL motion before/after: section 3.

## 8. Negative control of the cold gate
`cold --kind hd --machine ste --variant nox` (the packet's X delta is never committed, so the pointer cannot move horizontally): the cold boot **fails** in the menus: `RuntimeError: screen name not reached` (the click on "Action" at x = 415 never lands), exit 1. The gate fails on a pointer that does not follow the mouse.

## 9. Limits and open points
- Measured on Hatari only (the user's emulator). On real hardware the IKBD sends packets at a much finer cadence, so the alias is smaller there; the halving fix applies equally.
- Host steps below 3 px per 10 ms never reach the game in my Xvfb setup (section 2); the user's Wayland/XWayland delivery may differ. The filter is rate independent; the `model` check covers any packet sequence.
- The pointer now lags the mouse by about 20 ms and stops 40 ms after the mouse. A 4-tap box (`divs #4`, one more history word per axis, state 22 bytes) is a small change if less ripple is preferred over latency.
- The 3D view's one-VBL pointer vanish per frame (jerk.md) is not touched.
