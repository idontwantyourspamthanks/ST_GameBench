## 2. Role

`$38cd0` **writes already-clipped, already-projected polygon spans into the 320×200 4-plane screen**. It is not a projector or a sorter; it is the last stage. It contains no pixel loop of its own — it decodes (colour, mode, alignment) into one of ~112 pre-unrolled routines and `jmp`s to it.

Entry contract (live-verified, §7):

| Reg | In | Meaning |
|---|---|---|
| `d0` | `$67a6.l` | draw base; upper word (`$0006`/`$0007`) survives the fill loop's `move.w (a0)+,d0` so 16-bit span offsets become full screen addresses. `$67a6` is written only by the flip routine `$26e98` (`move.l (a6),$67a6.w` at `$026eb8`, a6 = `$770e`, after swapping `$770e`/`$7712` and setting `$ff8201`), so it mirrors the buffer-base slots and can carry a window offset: `$00060000`/`$00070000` observed live at entry and in the RAM dump, `$000600C0`/`$000700C0` observed by `SpanFill` mid-frame |
| `d2` | `$6808.w` | fill selector: high byte = dither class, low byte = colour index |
| `d3` | `$6806.w` | mode (0 = table `$3ba5a`, non-0 = `$3baea`); only low byte tested by `tst.w d3` |
| `d6` | `$180ee.w` | first y of group; `d6&1` (y-min parity) picks the even/odd entry = dither row phase |
| `d7` | `$180ec.w - $180ee.w` | **span count** (dbra counter) |
| `a0` | `$7b6b0 + 4y` | per-span `(offset word, mask word)` pairs |
| `a1` | `$7b9d0 + 4y` | per-span mask words |

Outputs: words written to `screen_base + offset` at `(a2)+`. Clobbers d0–d7/a2–a6; callers save with `movem.l d0-d7/a0-a6,-(a7)`.

Dispatch (`$38cd0`–`$38d20`, 20 bytes of table chasing):

```
038cd0: move.w d2,d0 / clr.b d0 / sub.w d0,d2   ; d2 = colour low byte
038cd6: asr.w #$2,d0                            ; d0 = (class<<8)>>2 = class*64
038cda: tst.w d3 ; bne -> lea $3baea(pc),a2 else lea $3ba5a(pc),a2
038ce6: move.b (a2,d2.w),d2 ; add.w d0,d2 ; add.w d2,d2
038cf2: move.w ($3b85a,d2.w),d2                 ; -> offset into code table
038cfa: adda.w d2,a2   (a2 = $3ac1a)
038d04: add.l (a2)+,d2 ; add.l (a2)+,d3          ; d2/d3 = $38cd0 + rel32 entries
038d08: move.w (a2)+,d4 ; move.w (a2)+,d5        ; per-plane mask constants
038d0c: movea.l (a2)+ ×4 -> a3,a4,a5,a6          ; per-plane fill constants
038d14: andi.w #$1,d6 ; beq -> jmp (d3) else jmp (d2)
```

Tables are `rel32` to `$38cd0` (position-independent). Table index = `byte_table[colour&$ff] + (class<<8)>>2`, then a word offset — three dependent loads before any pixel is written.

Fill routine shape (all instances, e.g. `$38d22`, `$39e4e`):

```
3018      move.w (a0)+,d0     ; screen word offset
3418      move.w (a0)+,d2     ; mask/pattern
2440      movea.l d0,a2       ; a2 = base|offset
9059      sub.w (a1)+,d0      ; branch selector
6b..      bmi  -> wide-span path
66..      bne  -> skip/other
...       4× and.w/or.w d2,(a2)+   ; one 16-px group = 4 planes
5040/24cb/24cc  addq.w #$8,d0 ; move.l a3,(a2)+ ; move.l a4,(a2)+ ; bne  ; solid run
51cf....  dbra d7,<top>
4e75      rts
```

Each `dbra` iteration = **one span** (one 16-pixel group, or a solid run). 4 consecutive words = 4 interleaved bitplanes of the same 16 pixels.

### 4.3 Clipper edge loops

`$38442` (1.13 %) walks each polygon's edge list twice: first pass AND/ORs the per-vertex outcodes (`$3847a`–`$38496`, 0.09 % each, `move.w (a0,d2.w)` 14 cyc + `move.w $6(a0,d4.w)` 18 cyc per edge), then, if the AND is 0 and the OR non-0, a second pass pushes edges and sets bit 7. Pure index chasing through the vertex array — memory-bound, no arithmetic. `$385b4` (1.32 %) is the same shape with plane tests via `btst.l d7,d0`, and `$38736` (0.91 %) is the per-plane insert walk that `jsr (a6)`s to the intersection stub.

## 6. Optimisation opportunities (STE)

| # | Idea | Est. saving | Risk |
|---|---|---|---|
| 1 | **Blitter fill for wide spans.** The solid run (`move.l a3,(a2)+`/`move.l a4,(a2)+`, 50 cyc per 16 px) is a constant-pattern masked write — exactly a blitter `DST`+`HALF` op. Only worth it above ~4 groups/span (blitter setup ≈ 200 cycles) and needs `BLITTER` bit-plane striding = 4-word interleave. Apply to the `$39c8a`/`$39600` families only, keeping CPU for short spans. | up to 3–4 % of frame | High: HOG mode stalls the CPU, interleave addressing, and the mask edges must still be CPU-done |
| 2 | **Collapse the 3-table dispatch into a 256-entry long table** indexed by `$6808` low byte (+ one `btst` for mode), precomputed whenever the palette/mode set changes. Removes 3 dependent memory loads and the `asr/add/add` chain from all ~155 calls/frame (~40 cycles each). | ~0.2 % | Low: pure indirection change, pixel-identical |
| 3 | **Merge the `(a0)`/`(a1)` streams** into one 6-byte-per-span record so each iteration does one `move.l (a0)+` + one `move.w (a0)+` instead of two `move.w (a0)+` plus `sub.w (a1)+`. Saves ~12 cycles/span × ~240 spans/frame. | ~0.2 % | Medium: touches `$3c5e2`'s output format (coordinate with the `SpanFill` agent) |
| 4 | **Reciprocal table for the projection divide.** `divs` at `$38406`/`$38408` → `muls` by `1/z` from a 2–8 KB table in fast RAM, or shift-normalise so `z` lands in a byte index. Halves per-vertex cost. Only pays off with many vertices (this scene: 0.08 %; a busy vehicle scene will be several × more). | 0.05 % here, more in busy scenes | Medium: rounding must match `divs` truncation or pixels shift by 1 — gate on screenshot diff |
| 5 | **Skip the second edge pass in `$38442`** when the first pass's OR already proves all-inside (currently it re-walks the list to push edges). | ~0.3 % | Medium: must prove the OR test is sufficient; `[INFERENCE]` |
| 6 | **Visual tradeoff candidate:** the dither classes (16 of the ~112 instances, incl. the 6.13 % family) exist to fake intermediate colours. If a flat colour is acceptable, a solid-only path removes the `or/and` mask dance (16 cyc × 4 per span) entirely → could reclaim ~2–3 % of frame. Needs your sign-off on before/after shots. | 2–3 % | Visual change |
