(master `games/done/powermonger/work/dumps/entry10a6.bin`, `$10a6..` = its game proper at the stage-2 hand-over; WW1 `wwdepack.resident_image(AUTO/WW1.PRG)`, `$576..$1d2ad`, byte-identical to the

## Method
1. 12-byte windows occurring exactly once in each image give the candidate address shifts (WW1 - master): `python3 tools/addrmap.py shifts` lists the top 40 of 187 distinct anchor shifts, the dominant ones
   (`+0xd74` main loop and window code, `-0xa6c` flip / interrupt part, `-0x570` composer and font, `-0x610` protection, `+0x3f2` resource loader, `-0xb30` start-up, ...).  The shift is NOT constant:
   it changes at function boundaries, so every address is mapped on its own.
2. For a master address X the shift whose 64-byte window around X agrees best with the WW1 image is taken (`bytes` column = agreeing bytes of 64; absolute operands differ by design, so 40-64 is normal).
3. **Spot-check by instructions** (`python3 tools/addrmap.py check`): the first 8 instructions at the mapped WW1 address are disassembled (capstone, 68000) next to master's; the column `insn` counts equal mnemonics.
   Every code site and routine below agrees on every compared instruction except `tick_head` (0/8) and `1a4da` (4/8), which were looked at by hand (marked **); the data rows (tables, font) are compared by bytes only.
4. A variable is mapped through the code that uses it: every occurrence of its 4-byte operand in master's code is mapped to WW1 and the operand found there is the vote (`votes` = occurrences that agree / occurrences found).
5. Dynamic confirmations (Hatari, EA original, `work/runs/`): see the last table.
