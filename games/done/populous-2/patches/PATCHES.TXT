WHICH VERSION TO USE (three builds of this release)
  Hard disk (folder POPS2)   ST, STE, Mega STE, TT, Falcon; 2 MB RAM or more.
                             In-game SAVE/LOAD to NAME.GAM files in FILES\
                             (not on the Falcon: use HAGA's statesave there).
  Floppy (Populous2_boot.st) ST, STE, Mega STE; 2 MB RAM or more.
                             Saves go to a separate save disk (included).
                             Does not start on a TT or Falcon.
  Low-RAM floppy             ST, STE, Mega STE, Falcon; TT at 8 MHz only.
  (Populous2_lowram.st)      512 KB RAM or more (the plain-ST sprite speed-up
                             needs 1 MB). Saves on the game disk, 3 slots.
  All three have the same enhancements (fixed 6.25 turns/s speed, 60 Hz,
  faster sprites and pointer, tooltips, no manual question).

Changes vs the original HAGA release:
- Fixed game speed: the world runs 6.25 turns per real second on every machine (ST, STE, Mega STE, TT, Falcon) at
  50 and 60 Hz. The original ran one turn per drawn frame: about 6 to 9 a second on an 8 MHz STE, about twice that at
  16 MHz, and faster still on a TT. The pointer, scrolling and tooltips stay smooth while the world waits; commands
  given between turns are queued and run in order, one per turn, as on a stock 8 MHz STE.
- Runs at 60 Hz: the game refused 60 Hz machines ("SORRY PAL MACHINES ONLY") and, past that, wiped memory when the
  pointer reached the bottom of the screen. Both fixed; at 60 Hz it draws exactly the same frames as at 50 Hz.
- Faster, same picture: sprites are drawn with the STE blitter with empty-row trimming (a pre-shifted cache on a plain ST),
  the pointer is only redrawn when something changed, the 32 KB background copy is unrolled, the land-score stagger divide is
  replaced by a shift, and 2 MB+ machines use triple buffering (3rd buffer at $90000) plus STE DMA sound for SFX (plain ST keeps YM).
- Low Detail toggle: press F7 during map play to toggle High / Low detail (with a brief sky-strip flash; F1-F6 remain effect
  categories); Low throttles minimap per-peep dot plotting to 1 in 4 turns.
- Tooltips: pointing at an icon shows its name and its key (the game's own F1-F6, 1-5 and keypad keys) in the sky at
  the top of the screen.
- Falcon: the sample player no longer risks a bus error on the Falcon's sound chip.
- Fixed: on a TT or Falcon the mouse pointer was missing on the menus and in play (also in PP's release); it is now drawn
  every frame there. ST, STE and Mega STE are unchanged.
- Garbled mouse packets (e.g. while the blitter is busy) are ignored instead of crashing the game.
- The manual question (Zeus's statue question: "how many statues have been built in the likeness of this head") is skipped:
  the game starts straight into play. PP's build already accepted any answer; now the screen does not appear at all.

The main menu (the stone-framed screen with CREATE YOUR DEITY / CONQUEST
GAME / CUSTOM GAME / LOAD GAME) carries a small "v@VERSION@ enhanced by
dad_prg" line in the lower part of the slate panel; nothing else on the
screen changes.

Requirements and usage: as in README.TXT (2 MB RAM minimum).
Run RUNME.TOS from a hard disk / GEMDOS drive, with FILES\ next to it.
Tested on Hatari 2.6.1: STE 2 and 4 MB (TOS 1.62, 8 and 16 MHz, 50 and 60 Hz), ST 2 MB (TOS 1.04), Mega STE 4 MB
(TOS 2.06), TT 4 MB (TOS 3.06), Falcon 4 MB (TOS 4.04). Not tested on real hardware.

The original game keeps its statesaves on the HD build: keypad / saves the
game state to GS00.TOS, GS01.TOS, ... in the folder HAGA runs from (it looks
for C:\GAMEX\ first). In-game SAVE GAME / LOAD GAME work on ST/STE/Mega STE/TT, files NAME.GAM 56,690 B in FILES\ or the typed drawer; complete on disk when the game returns to play; not on the Falcon (DISK FILE ERROR; use the HAGA statesave).
