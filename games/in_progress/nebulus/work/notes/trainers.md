# Nebulus trainers: stop the timer, remove enemies (NebTrainers)

Tags: **[obs]** observed in Hatari 2.6.1 (raw lines quoted), **[disasm]** read from `tools/m68dis.py` on my 1 MB dumps, **[INFERENCE]** not verified.
All addresses are RAM, 1 MB STE, TOS 1.62, the resident game after load (code `$33000..$40000`, data to `$7c000`).
Files: `work/train/tools/{nt.py,exp1.py,exp3.py,exp4.py,exp5.py,exp6.py,recipe2.py}`, dumps `work/train/dumps/tower_{a,b,c}.bin`, snapshots `work/train/snap/{tower1mb,play1mb}.sav`, disassembly `work/train/dis_33000_40000.txt`, shots `work/train/shots/`, patch sources `patches/nt_{freeze,noenemy,keys,tmrhook,enhook}.s`, blob image `work/train/nt_keys_blob.bin` (118 B at $76c00).

## 0. How to get into the tower (proven, 4 cold boots)
`Nebulus(workdir=...)`; `sleep 16`; ONE `keypress(57)` (ends HW-detect); `sleep 24`; `h.key('Right',0.5)`; `h.key('Control_R',1.0)` (= joy1 fire, arrives as ikbd bytes `$1d,$80,$9d,$0` in `$38498`). `boot_to_game()`'s six extra spaces make the fire press fail [obs: recipe.py `lead`/`leadd` -> `$3ad98` stays 0; `nospace`/`mine` -> `00 20 00 00 00 00`]. In-tower test: word `$3ad98 != 0` (`$20` = "t-400"), `$33938 == 1` (timer running), `$33a20 == 0` (player idle).
**Debugger gotcha**: `w` takes BYTE arguments only. `w $3b0aa $6000` -> `Illegal byte argument: 0x6000!`; `w $3398c 0` writes one byte. Use `w $3b0aa $60`, `w $3792c $4e $75`, `w $3398c 0 0 0 0 0 0 0 0`.

## 1. Timer
- **Variable** [disasm+obs]: three words `$3ad98` (hundreds), `$3ad9a` (tens), `$3ad9c` (ones). Each = digit*8 + sub-step, range 0..`$4f`; displayed digit = `(w>>3)&$f` (sub_03d236 at $3d23a-$3d26c reads them that way). "t-400" = `00 20 00 00 00 00`; `00 18 00 48 00 48` = 399.
- **Tick** sub_03b0a4 (only caller `$3dfa4 jsr`, once per game-loop iteration after the flip): `tst.w $33938 / beq.w $3b0fa` (gate: `$33938` set to 1 at `$3bb8a` when play starts, cleared at level start `$3dc0c`, level end `$3de08`, death `$3a744`); `subq.w #1,4(a0)`; on <0 reload `$4f` and borrow from `$3ad9a`, then `$3ad98`; the tens/hundreds words are then rolled down to a multiple of 8 one step per call (`$3b0de-$3b0f8`). So 8 calls = 1 displayed unit: **the clock is frame-rate dependent** (one tick per game-loop iteration, not per VBL). [obs: exp1 A, ~14 units in 230 VBL once; not a clean rate measurement.]
- **Time up**: `$3b0fa-$3b106` ORs the three words; Z=1 => `$3dfaa beq.w $3de82` -> sub_03d1c2 prints "Time Limit Up !!" ($3cffe) [disasm].
- **Initial value**: sub_03adae (`$3adae`, called `$3dcac` at level start) reads the BCD word table at **`$3ad9e` indexed by tower `$3390c`**: `0400 0450 0500 0550 0600 0650 0700 0750` (400..750) and adds the carry `$33934/36` (cleared `$3dbc2`), then splits into the three words (sub_03add2, cap `$99`). [obs: dump `03ad9e: 0x400 0x450 0x500 ...`; tower 1 started at `(32,40,0)` = 450 in exp4.] **So the limit is code/data of the game exe, not the level grid.** NebLevel2: literal at file offset `$3C8E` (their number).
- **Freeze, minimal**: byte `$3b0aa`: `67 -> 60` (`beq.w $3b0fa` -> `bra.w $3b0fa`; the digit-zero test still runs but the digits never change). [obs, my snapshot `tower1mb.sav`, exp1 B: `timer words (32, 0, 0)` for 6 samples over 1167 VBL while control A counted down; Main's snapshot, exp6 byte form: `vbl 2957 / 3188 / 3418: 0003AD98: 00 20 00 00 00 00`, `0003B0A4: 4a 79 00 03 39 38 60 00 00 4e`]. Shots `work/train/shots/ABC_m.png` row B: HUD stays t-400. Works at any moment; survives level change [obs exp4: tower 2 timer `(32,40,0)` constant 10 samples]. Side effect: Time Bonus at level end stays at the starting value [INFERENCE: bonus reads the same words, `$3d236-$3d29a`].

## 2. Enemies
- **Table** [disasm, live-dumped in exp1]: struct-of-arrays at **`$33944`**, 6 slots (words, slot = `$33944+2*i`), field stride `$0c`: `+$00` X (tower angle 0..$7f; or screen X for the flyer), `+$0c` Y (0..$3ff), `+$18` sprite frame, `+$24` depth sort key, `+$30` draw X, `+$3c` counter, **`+$48` state**, `+$54` speed/direction, `+$60` aux, `+$6c` target state. Slots 0-3 (`$33944..$3394a`) = creatures; slot 4 (`$3394c`) = the player's shot (spawned by sub_03a376, state 1); slot 5 (`$3394e`) = the player's hit box (sub_03a4e6 sets X/Y from `$33a16/$33a18`). State words of slots 0-3 live at `$3398c,$3398e,$33990,$33992`. State 0 = inactive: skipped by the update (sub_03b482 `$3b492`), the draw sort list (sub_03b3d8 `$3b3f6`, states 0 and 7 are excluded; 7 = the flyer, drawn by sub_039600 `$39612`) and the overlap test (sub_03b7d6). Live samples [obs exp1 A]: states `(8,2,0,0)`, `(8,2,7,0)`, `(8,6,0,0)`; 8 = vertical mover (Y += `+$54`), 2 = walker, 6 = spawn animation, 7 = flyer entering from the side.
- **Spawn** sub_03792c (only caller `$3df42`, every game-loop iteration): returns at once if player state `$33a20` is 8/9/10; otherwise looks for a free slot (state 0) among 0-3; **the enemy placements are in the tower grid** (`$327f0` + column*256 + row, 16 columns x 256 rows; column = angle/8, row = Y/4): a scan pointer `$3393c` advances one cell per call; a cell with bit7 clear and `(v&$70) != 0` starts an enemy at that cell (type: `$10`->walker `$6c=2`, `$20`->`$6c=1` speed 1, `$40+`->`$6c=8`, `$60+`->`$6c=9; state set to 6 at `$37ab2`); the scan stops at row `$3391b` (= screen top row). When the pointer reaches row `$33913` the "time-waster" flyer countdown `$339bc` (init `$7d` at `$3dc5e`, reset `$3b4f8`) runs and at 1 sets state 7 (`$37adc`) with direction `$339be`. [disasm]
- **Hit** sub_03a572 (player state machine, `$3dde0`): `bsr sub_03a4e6` -> overlap vs slots 0-3 via sub_03b7d6 plus a special flyer box (state 7, X `$41..$54`) -> player state 7 (`$3a672`), energy `$3392c -= 2` (starts `$64`, the "Technique" bonus), usually followed by a fall into the sea. Not lethal by itself, but with no input the frog dies within seconds of the level start in the stock game [obs exp5 first run: game over to title in ~30 s].
- **Does anything depend on enemies?** `xref` of the enemy table: only `$3795c` (spawn), `$39608` (draw), `$3a510` (hit), `$3b3c0/$3b3d8/$3b482/$3b7da` (update/sort/overlap). Level end: `$39df2 bsr sub_03aae8` (tile under the player: bit7 set, low 2 bits = 3 = door; `d0 & $40` != 0 = exit door, grid byte `$c3`; tower 1 has it at column 4, rows 43-45) -> `$39e00 move.w #1,$33a46` -> `$3a116` player state 4 ... `$33a46`=2 -> `$3de08` bonus screen -> `$3390c++`; after tower 8 (`$3de4a cmpi #8`) "Congratulations" (`$3d1e4`). No enemy variable is read anywhere on that chain. [disasm]
- **Disable options** (least side effects first):
  1. **Skip the spawn** (`$3792c: 4e 75`, rts as first instruction) + clear the four state words once if applied mid-level. Nothing spawns (map creatures and the flyer), nothing is updated/drawn/hit, all other code untouched; the scan pointer simply stops, so toggling back resumes where it stopped. [obs exp1 C: states `(0,0,0,0)` on 6 samples over 1167 VBL vs `(8,2,7,0)` control; shots `ABC_m.png` row C show no creature]. Also confirmed through a tower change [obs exp4].
  2. Make the hit test never hit (`$3a508 bcs.w` -> nop / `$3a4e6` return carry clear): creatures stay visible and harmless; flyer box is a second return path (`$3a526/$3a52a`). Not tested.
  3. Clear only the counts: no count variable exists (the table is fixed-size, state 0 = free), so it is not applicable.
- **Level completable with enemies off** [obs exp4 on a cold-boot tower, both pokes on, door-entry state forced by `w $33a46 0 1` + `w $33a20 0 4` + `w $33a1e 0 0`, i.e. exactly what `$39e00/$3a116` set]: `e0 st 4 33a46 2 tower 0`, `e1 ... 33a46 4 tower 1 timer (0,0,0)`, bonus (submarine) screen `end_m.png` 2nd panel "TIME BONUS", then `e6 x 4 y 8 st 0 33a46 0 tower 1 run 1 timer (32, 40, 0)`: tower 2 (blue) running with timer frozen at 450 and enemy states `(0,0,0,0)`. NOT done: a genuine climb to the exit door by player input (teleporting the frog (x=32,y=172) hung the game twice: a large Y jump breaks the scroll/draw loop, so do not use position pokes).


## 3. Delivery: patch sites (house format files in `patches/`, all verified against the dump bytes)
Sites in the loaded game (RAM, 1 MB STE). "orig" bytes are from `work/train/dumps/tower_c.bin` (identical in the 3 dumps; the code is not self-modified).
| patch file | address | original | new | what it does |
|---|---|---|---|---|
| `nt_freeze` (static, no blob) | `$3b0aa` | `67 00 00 4e` (`beq.w $3b0fa`) | `60 00 00 4e` (`bra.w $3b0fa`) | timer never ticks (sub_03b0a4 tick head always skipped) |
| `nt_noenemy` (static, no blob) | `$3792c` | `30 39` (`move.w $33a20.l,d0`, 6 B insn) | `4e 75` (`rts`) | enemy spawn routine returns at once: nothing spawns; not retroactive |
| `nt_keys` (toggle, owns blob) | `$3dcf4` | `4e b9 00 03 85 3a` (`jsr $3853a.l`) | `4e b9 <NT+$08>` | frame-loop key poll: original poll, then T/E edge detect on the game's last-IKBD-byte cell `$38498` |
| `nt_tmrhook` (requires nt_keys) | `$3b0a4` | `4a 79 00 03 39 38` (`tst.w $33938.l`) | `4e b9 <NT+$40>` | timer tick head: hook returns Z=1 while frozen, else the original `tst.w $33938.l` |
| `nt_enhook` (requires nt_keys) | `$3792c` | `30 39 00 03 3a 20` (`move.w $33a20.l,d0`) | `4e b9 <NT+$58>` | spawn head: with E on clears the 4 creature state words `$3398c..$33993` and returns to the caller without spawning; else the original insn |
`nt_freeze`/`nt_noenemy` conflict with the toggle set (same sites); `nt_noenemy` and `nt_enhook` overlap at `$3792c`.
**Blob** (inside `nt_keys.s`, `NT equ $76c00` is a PLACEHOLDER address): `NT+0` prev byte, `NT+2` `frz` word, `NT+4` `noen` word (initial values = boot default; `$ffff` = on at start), `NT+$08` key hook (48 B), `NT+$40` timer hook (18 B), `NT+$58` enemy hook (30 B); `$76c00..$76c75` = **118 bytes**. Position independent except the three call sites (absolute `jsr`) and the game addresses; no self-modifying code (safe for 030 caches). Built from the sources with vasm `-Fbin -no-opt -m68000`; the blob image used in the live test is `work/train/nt_keys_blob.bin`.
**Keys**: raw IKBD make `$14` (T) and `$12` (E) read from `$38498`; `$14/$12` have bit 4 set, joystick state bytes never have bits 4-6 set (same discrimination as `$3853a`). T and E are not game keys (E is idx 16 in the game's key table, ignored in play); P pauses, Q quits to the title, F1-F8 select towers only after the HELLOIAMJMP cheat. A tap shorter than one loop iteration (~40 ms, only the LAST ikbd byte is kept) can be missed [INFERENCE from the ISR].
**[obs] Live test of the final blob** (exp5.py, cold boot, `loadbin /tmp/ntb.bin $76c00`, call sites written with byte `w`; log quoted): `hooked frz 0x0 noen 0x0 ... enemy states (8, 2, 7, 0)` -> after xdotool `e`: `noen 0xffff prev 0x92 ... states (0, 0, 0, 0)`, then 3 samples (`vbl 3479/3855/4230`) `st 0 run 1 states (0,0,0,0)` while the timer counts down `(24,64,65) (24,48,37) (24,32,9)`; after `t`: `frz 0xffff prev 0x94`, timer `(24, 24, 36)` identical on 4 consecutive samples (`vbl 4520..5647`); `t` again: counts `(24,16,25) -> (16,72,65)`; `e` again: `noen 0x0 prev 0x92 states (8, 2, 0, 0)` (enemies return). Shots `work/train/shots/hook_m.png` (HUD t-335 / t-334 frozen, frog alive, no creature; 3rd panel = title after game over: unattended frog died once enemies were back).
**Retroactive?** Hook version: YES, E clears the four creature state words every iteration, so creatures already on screen vanish on the next frame [obs: states `(8,2,7,0)` -> `(0,0,0,0)` right after `e`]. Static `nt_noenemy` (`rts`): NO, it only stops spawning; creatures alive when it is applied keep running (none exist at boot). Turning E off again: spawning resumes where the grid scan pointer `$3393c` stopped (creatures reappear as the scan reaches their cells) [obs: `(8,2,0,0)`].
**Restart / next tower**: the flags live in the blob, not in game variables, so they persist across death, game over -> title -> new game and tower changes. [obs] freeze across a life loss (exp1 B: timer reloads to the start value `(32,0,0)` and stays), freeze + enemies-off across a tower change (exp4: tower 2 at `(32,40,0)`=450 constant, states 0; this used pokes, not the hook; the hook was not run through a tower change). Pause (P, `$38614`) waits in its own loop: no key poll there, so T/E are ignored while paused [disasm]; not tested.
**Where to put the blob** (NebBoot2 decides): 118 B of RAM that stays free during play. Candidates: (a) `$76b0c..$77ec5` (5049 B, zero in all three of my dumps: title/high-score + two tower states; no absolute reference found in the disassembly of `$33000..$40000`) [INFERENCE: free]; (b) a payload above the game on a 1 MB machine (free map not measured; the 512 KB mode has nothing above `$80000`); (c) game-exe padding, e.g. a repack (NebLevel2) can place the blob in an extended segment; `$3e038..$3e057` (32 B) is too small. The sites themselves are in the game exe, so they work with any carrier that patches the loaded code. If the blob is placed elsewhere edit `NT` in the three `nt_*.s` files.
Interaction: any other patch around the key poll (`$3dcf4`, input-lag work on `$3853a`/`$384fc`) must keep that call; the tick/spawn sites are independent of input work. The timer is frame-rate dependent (section 1): a frame-rate patch changes the clock speed unless it is compensated; the freeze is immune.

**Findings that change how the trainers must be used / what is not perfect**
1. The key hook runs once per game-loop iteration, but only the LAST IKBD byte is kept and some sequences (the death/hit animation `player 7/8/10`, level-start) stall the loop for longer than a quick tap: in one run a 0.3 s `e` tap was lost (`prev=92 noen=0000`, make byte overwritten by the break byte). Holding the key ~1 s fixed it every time (`tap ...: flag changed after 1 press(es)` on 9 of 9 taps in the final STE and Mega STE runs). The harness `tap()` holds 1.0 s and checks the flag. A real player holding a key >=0.3 s on a normal frame is fine; a key pressed during the death animation can be missed [obs once; mechanism INFERENCE].
2. The hook runs only in the in-game frame loop (title/intro/pause ignore T/E, see above), so toggles take effect in a tower only.
3. A key that is HELD across the end of a pause is seen as new by the hook afterwards (the make byte stays in `$38498` until another byte arrives; a tap with its break byte does not) [INFERENCE from the ISR/hook logic, not run].

**NOT proven**: real hardware; TT/Falcon (the blob address and the `$38498` ISR cell were only seen on STE/Mega STE Hatari); a genuine player-driven climb with the toggles on (the door and the life loss were forced with pokes); trainer toggles during 2-player mode, towers 3-8 and the end-of-game screen; the time bonus with the clock frozen; the held-key-through-pause case; a RAM comparison on the 4 MB machine; GXUT270 F9 save/restore of the patched state.
