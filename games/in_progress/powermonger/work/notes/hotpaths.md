# Powermonger hot paths (8 MHz STE; profiles in `work/prof/`, dump `work/dumps/*.bin`, listings via `tools/m68dis.py` and `tools/pmprof.py`/`pmreport.py`)

Method: Hatari `profile save` over 150 VBL (120 VBL-handler runs counted at `$1282`), per-address instruction counts + cycles. "Function" = a contiguous block of executed addresses (gap <= 64 bytes), because the game code is hand-written with jump tables and many routines are reached by `jmp`/`bra`, so call-target bucketing (as in `pmprof.Prof.table`) merges and splits them wrongly. Counts are per loop pass (a pass is a presented frame: `$13040` count = 5 / 9 / 9 passes at 8 MHz).

## The five most expensive pieces
1. **Textured terrain span fill `$e39e-$e5aa` (34-40 %)**. Called once per terrain triangle (131 triangles per pass); the setup reads (u, v, count) runs and steps two texture coordinates along each scanline in 16.16 form, fetching one dithered 4-plane texel group per 16 pixels with a mask. Per scanline: 2-3 `and.l`/`or.l` read-modify-writes. Excerpt (`$e420`, per left-edge group, 5216 times in the idle window):
```
00e420  lsr.w #$1,d4 / lsr.w #$1,d5 / swap d4 / add.l a3,d4 / swap d4 / subq.w #$1,d7 / bne.b $e436
00e456  add.w d4,d4 / add.w d5,d5 / move.w (a6,d5.w),d6 / move.w (a6,d4.w),d0   ; table lookups
00e462  lea.l (a1,d0.w),a2 / sub.w d0,d6 / bge.b $e46e / bne.b $e4a6            ; span length in 16-px groups
00e478  move.l -$80(a6,d0.w),d3 / and.l -$40(a6,d0.w),d3                       ; left/right edge masks
00e48e  and.l (a2),d1 / and.l (a5)+,d0 / or.l d1,d0 / move.l d0,(a2)+           ; masked texel store, planes 0-1
00e496  and.l (a2),d3 / and.l (a5),d2 / or.l d3,d2 / move.l d2,(a2)             ; planes 2-3
00e49e  lea.l $a0(a1),a1 / bra.w $e420                                          ; next scanline
```
   Same design family as Midwinter's polygon fill (edge walker + table-driven span fill) but heavier per pixel: it is a **texture-mapped** triangle fill (per-pixel u/v interpolation and a 16.16 DDA, masked read-modify-write on 4 planes), where Midwinter 2 fills flat/dithered spans (`spanfill.md`: fill variants `$38d22-$3bb00` 11.6 %, walker 6 %). The span filler here is 2.5-3x Midwinter's biggest bucket and there is no hierarchical cull: every cell of the 64-column terrain window is submitted as two triangles (`$f898` loop, `bsr $ef62` x4 per cell, `$fd04-$fd6a`).
2. **Masked sprite blitter `$12326`/`$124a8-$12574` (11-17 %)**: men, trees, houses, boats, angels. 17.9 k cycles per call (~20 calls/pass), per scanline: 4 words loaded, `ror.l d0` by the pixel shift (`$124b2..$124dc`, 1104 times each), AND with the mask, OR into the screen (`movem.w d4-d7,-$8(a0)`).
```
0124ae  moveq #$ff,d3 / move.w (a1)+,d3 / ror.l d0,d3       ; mask word shifted by d0 (0-15)
0124b8  ror.l d0,d4 ... ror.l d0,d7                           ; 4 bitplane words shifted
0124e2  movem.w d4-d7,-$8(a0)                                 ; store 4 planes
```
3. **Timer A sample IRQ `$1af32` (3.5-26 %)**: digital sound through the YM volume registers (`movep.l d1,-$720f(a0)` with a0 = `$fa0f` -> `$ff8800`), ~3.7 kHz, 264 cycles per interrupt, reads `$5c357`. Costs nothing when no sample plays; while one plays it is a fixed 10-12 % of 8 MHz CPU.
```
01af38  movea.l #$5c357,a0 / clr.w d0 / move.b (a0)+,d0 / beq.b $1af6c   ; next sample byte
01af44  move.l a0,$1af3a.l / lea.l $fa0f.w,a0 / lsl.w #$3,d0
01af50  move.l $1af86(pc,d0.w),d1 / move.w $1af8a(pc,d0.w),d0            ; 6-byte YM register triple per level
01af58  movep.l d1,-$720f(a0) / movep.w d0,-$720f(a0) / bclr.b #$5,(a0) / rte
```
4. **Triangle setup `$ef62-$f240` (5-9 %)**: clips the 3 vertices (`$c7` = 199 rows, 0..$ff0000), sorts them, and computes the edge slopes with `divu` (about 330 divides/pass, `$f010-$f10a`):
```
00f00a  cmp.w d4,d1 / ble.b $f01a / swap d4 / divu.w d1,d4 / andi.l #$ffff,d4   ; slope = dy<<16 / dx or (dy<<8)/dx
00f01a  lsl.l #$8,d4 / divu.w d1,d4 / bvc.b $f028 / move.l #$10000,d4           ; overflow clamp
```
5. **Buffer copy `$12ce0` (4.6-9 %)**: `movem.l (a0)+,d2-d7/a2-a3` + `movem.l ...,(a1)` x500 = 32 000 bytes (the whole screen) every pass, 165-177 k cycles; also the **mouse pointer VBL code `$1378-$14e4` (7 % at 8 MHz, 11 338 cycles per VBL, 13 VBLs per pass)**: restores 16 saved lines (`$1c49e`) and redraws the pointer on the back buffer at every VBL even when it did not move.
```
012ce0  movem.l d1-d7/a3,-(a7) / moveq #$20,d1 / move.w #$1f3,d0
012cea  movem.l (a0)+,d2-d7/a2-a3 / movem.l d2-d7/a2-a3,(a1) / adda.w d1,a1 / movem.l (a0)+,... / dbra d0,$12cea
```

## Landscape engine compared with Midwinter
* Midwinter (`games/in_progress/midwinter/work/notes/render.md`): geometry (40 %) + raster (40 %) per frame, edge/DDA overhead dominates, interior stores 1.3 %, flat/dithered fills; a standing frame is recomputed identically (95 % redundant), so static-frame skip paid 5x. MW2 (`midwinter2/.../spanfill.md`): fill variants 11.6 %, walker 6 %.
* Powermonger: **raster-bound** (terrain fill 34-40 % + sprite blit 11-17 % + triangle setup 5-9 % + copy 8 %); geometry here is tiny (no per-vertex transform in the profile: the map is a fixed 64x64 height grid, `$3f364`, projected by table: `$f898` loop 2 %). Per pixel work is higher because each pixel of the terrain is a texel (dithered colour from `$e3e6` tables), with a mask RMW.
* **Static-frame skip** (Midwinter's biggest win) applies only partly: in map_idle two consecutive flips differ by rain, animation tick `$57fec`, and walking men; a scroll/zoom/rotate-free scene without moving objects would redraw identical pixels. [INFERENCE] not measured.

## Wasted / redundant work, ranked (all [INFERENCE] estimates unless stated; pixel-identical unless stated)
1. **Sample IRQ**: 10-12 % of the CPU whenever a sample plays, and map_idle shows 26 % at the start. Replace the YM volume-register playback by STE DMA sound (audio changes slightly but video is untouched). Gain while playing: +10-26 % (8 MHz).
2. **Mouse pointer redraw at 50 Hz when frames come at 2-4 fps** (7 % of cycles, 11.3 k cycles per VBL): skip the restore/draw when the pointer did not move and the back buffer was not swapped. Pixel-identical. +5-7 %.
3. **Sprite blitter shift work** (`ror.l` x5 per scanline): pre-shifted sprite copies, or the STE blitter (MW2 found the blitter not useful on short spans; sprites here are 16-40 px wide so a blitter test is warranted). Pixel-identical. 3-6 % of total.
4. **Whole-screen copy `$12ce0`** (8-9 %): copies 32 000 bytes each pass; only the 3D window region is rewritten by terrain/sprites. Restrict to the window (and skip the HUD columns). Pixel-identical. Saves up to ~20 % of the stage = 1.6-2 %.
5. **Terrain triangle fill**: 131 triangles/pass fully repainted even for cells fully covered by later cells (painter's algorithm, back to front, overdraw not measured). Occlusion culling is the largest lever but is not exact in general because objects are interleaved per cell. Static-frame skip (reuse the previous buffer pair when scroll, rotation, zoom, `$57fec` tick and every object in view are unchanged) is exact but rarely applies while men move.
6. **VBL wait**: 0.4-7.6 % (more at 16 MHz): the loop idles; at 8 MHz a pass already takes 13+ VBL so there is nothing to wait for.
7. Fixed-rate logic tick (below): not a speed-up but removes the CPU-speed dependence, required by the user.

## Fixed-rate logic tick (as in Midwinter) - how
The pass does `logic -> render -> flip` and the world is advanced only by the logic stage (`$13040-$13052`, `$1abaa`, `$1373c` camera/keys): it costs 43-74 k cycles = 2 % of a pass. Because render is 80 % of a pass, a patch can run the logic N times per render without moving the frame rate: derive the number of due ticks from the VBL counter `$6f304` (or a 50 Hz tick), run that many logic stages (cap ~4), then render once; skip the render stage when the buffer is not needed yet (not behind) and resync after long gaps. The state that logic writes (`$51b66` people, `$4e514` groups, `$4bb3a/c` scroll, `$57fec`) is only read by render after the logic stage, so the order is preserved. [INFERENCE] needs the A/B gate: restoring `get_men.sav` and comparing the visible buffer after N logic steps against the unpatched run at the same pass count.
