# PSG audit: YM2149 port direction (reg 7 bits 6/7) and select/write atomicity, 2026-11-20

Why: Midwinter 2 v1.5/v1.6 shipped with "music plays, no disk activity" on real STE/Mega STE. Its Amiga-music tick replaced the YM tick that kept PSG reg 7 bits 6/7
(I/O ports A/B = outputs) set; the game's sound init writes 0 there; port A (reg 14 = floppy drive-select bits 1-2, side bit 0) became an input, no drive was selected.
Hatari 2.6.1 does not model the direction bit, so every gate passed.

Tools (new, opt-in): `tools/psgcheck.py` (trace check, exit 1 on violations), strict Hatari (`tools/hatari-strict/`: patch + README; binary
`~/Code/AtariST/hattari-strict/build/src/hatari`), `Hatari(..., sound=True, trace_psg=True, strict=True)` / `HATARI_STRICT_PSG=1` in `tools/stharness.py`.

## Findings that need a game decision (nothing fixed here)
1. Hunter `snd_ymsilence` should write reg 7 absolutely (`move.b #$ff,2(a0)`), not `read | $3f`: it is the only remaining read-back dependency in a replaced sound path. Today it works because the title tune leaves bits 6/7 set (`$f8`, `$ff`); a different title tune or an earlier clear would silently kill the floppy on a real STE exactly as in MW2.
2. No other bug found. Midwinter 2 v1.6.1's `asn_mixer` select/write is two `move.b` (safe only because the FDC driver masks interrupts around its reg-14 pairs); making it one `movep.w` would remove the dependency.

## Not covered / limits
- Real hardware: nothing here was run on a real machine. The strict model is `reg 7 bit 6 = 0 -> drive-select/side pins read $ff`; port B (bit 7) is not modelled in the strict build (only warned about by psgcheck).
- Mega STE / TT / Falcon strict TOS boots (`tosprog.py` runs for TOS 2.06 / 3.06 / 4.04) were queued but not finished when this was written; the Falcon floppy runs above did boot TOS 4.04 in the strict build. Hunter / Powermonger / Populous / Moonshine were run on STE (Falcon for the Falcon-only cells), one boot each, 150-200 s.
- psgcheck sees only writes: read-modify-write interrupted between its read and its write is caught only when the interrupt changes the selected register.
