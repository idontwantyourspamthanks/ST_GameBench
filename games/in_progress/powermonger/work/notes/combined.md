## 1. The one conflict, and how it was resolved
`pmpatch.py verify` only prints per-patch site checks; the overlap checks are in `build` (`build_image`), and the first build of the new default set stopped with `site overlap: p7_triple_tail $1898+8 vs tt_ptr $1898`. **Both patches owned the flip's last instruction** `move.w #0,$2df8c.l` ($1898, 8 bytes). Blob ranges did not collide (p7 `$DB000-$DB3FF`, tt_ptr `$BA900-$BAFFF`, qol_* `$CD460-$CD60F` + `$CF000-$CFFFF`; the image-overlap check passed).
Fix: **`tt_ptr` moved to `$188c`** (`move.l d0,$2df78.l`, 6 bytes, the second half of the buffer swap; `jsr tt_flip`, whose first instruction is the displaced `move.l d0,$2df78.l`; all registers are saved, d0 stays intact for the `lsr.w #8,d0 / move.l d0,$8200.w` that follow). p7 is untouched, so every p7 gate keeps its meaning. The pointer is now drawn into the new displayed buffer BEFORE the base register is written (the old hook drew it right after): on a TT the new picture is never shown without it.
`pmpatch.py build` of the default set: floppy 36 sites, HD 40 sites, no overlap; `verify` ALL ok.

## 2. Pointer buffer with three buffers on the TT [obs, `pmcombined.py`, the `pointer buffer` line of each cell]
At every return of the main loop's flip (`$13872`) the pointer's saved-screen address `[$1c49a]` is compared with the buffer about to be scanned `[$2df78]` (one of A, B, C in rotation): **TT 134 of 134 flips: the pointer record lies inside the new displayed buffer; Falcon 67 of 67; STE / ST / Mega STE 0 of 23-28 (there the next VBL handler draws it, as always)**. `(L, D)` at flip entry on the TT is the rotation of p7 (`(A,C) x46 (B,A) x46 (C,B) x45`); screenshots show the pointer in 20 of 20 on every machine except the TT (19 of 20, section 4).
p7's argument that the draw target D' = X holds no pointer survives: tt_ptr's extra draw restores the pointer out of the previous L (`[$1c49a]`) and draws into the new L, so only L ever holds one.
