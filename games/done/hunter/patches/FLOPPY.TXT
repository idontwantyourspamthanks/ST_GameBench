What is in this set
  HUNTER_disk1.st   the game disk: the Paper Bag floppy release with a new loader stage, the patch code and, for the
                    STE sound, the sample bank.  ONE disk, extended format: 82 tracks x 11 sectors x 2 sides (923648 bytes).

What changed
  * Faster 3D view: the polygon filler, the edge set-up and the keyboard poll were rewritten; the picture is
    identical to the original, pixel for pixel.
  * STE sound (STE, Mega STE, TT, Falcon): the YM sound effects are replaced by the Amiga version's samples,
    played through the STE DMA sound chip (mono, 6258 Hz, two voices; the engine pitch follows the speed;
    on the Falcon the DMA runs at 12517 Hz with every sample doubled, same pitch).
  * A plain ST keeps the original YM sound (the sample bank is not even read).
  * 50/60 Hz: the original counts display refreshes. It asks for 50 Hz itself, but where the screen runs at 60 Hz anyway
    (hardware or an adapter that ignores that, an emulator set to 60 Hz) the world (walking, driving, turning, NPCs, timers,
    game clock, sound effect lengths) ran 20% too fast. It now runs in real time at 50 and 60 Hz; at 50 Hz nothing changes.
  * STE palette (STE, Mega STE, TT, Falcon): the Amiga's 4096 colours instead of the ST's 512 (a plain ST keeps the original).
  * The Amiga's sky and sea (ST, Mega ST, STE, Mega STE): six exact colour bands above the horizon, a solid sea, a warmer sky at
    dawn and dusk, and a separately lit dashboard (about 2% CPU). The TT and Falcon keep the original sky. With 2 MB or more the
    dashboard is the Amiga's own art and colours (the plain-ST floppy does not read the sample bank and keeps the ST dashboard).
  * Triple buffering (68000 machines, 1 MB or more): no wait for the screen between frames, up to about 9% faster; the TT and
    Falcon keep the original two pages.
  * Even mouse pointer: the pointer used to move by however many mouse reports had arrived since the last screen refresh, so an
    emulator's 53 reports per second against the 50 Hz refresh made it stop for one refresh and jump double about every 0.3 s,
    and the game halved only leftward and upward movement.  Now it moves once per refresh by the mean of the last three refreshes'
    motion, none lost or invented; all four directions are equally fast (right and down unchanged, left and up as fast as they).
  * Atari Jaguar pad (STE and Falcon enhanced joystick ports): the d-pad steers like the joystick, A or B is fire;
    C = Return, Option = Space, Pause = P, * = Esc, 1 = R, 2 = Help, 3 = L, 4 = A, 5 = F, 6 = C, 7/9 = cursor up/down.
    Other machines run exactly as before.
  * One-key items and weapon keys: in the 3D view 1-9 (top row or keypad) select the nine weapons of the item table's weapon
    row, H = medical kit, G = fuel can, J = parachute; each does what clicking that icon does (an item you do not own does
    nothing); ignored in the item table, log book, game options and pause.  Jaguar pad: # = H, 0 = G, 8 = J.
  * Controls guide: press P (or the pad's Pause) in the 3D view to pause and see a small panel with all the controls (the game's
    keys, 1-9 / H / G / J and, on an STE or Falcon, the pad buttons); press P again to remove it and carry on.  Nothing in the
    game changes, and the screen is restored exactly.
  * 2 MB or more: the dashboard uses the Amiga version's colours and art (STE-class machines, where the sound bank is read; with 1 MB it is unchanged).
  * The title screen shows a small, dim "v@VERSION@ enhanced by dad_prg" at the bottom; nothing else on it changes.
  * Hardening (v@VERSION@): the YM I/O port direction is now set explicitly (no known failure): the STE sound patch writes PSG register 7
    as an absolute value ($FF) when it takes over the YM instead of reading it back.  Nothing else changes.
  * The patches check every byte they replace; if the game code is not the expected one nothing is changed.

How to start
  Put HUNTER_disk1 in drive A (write enabled: the game saves to this disk) and switch on.  The disk autoruns
  HUNTER.TOS; press a key at the "Paper Bag presents" screen.  The title ignores keys while the game loads: wait
  until the menu appears.  Save games with ESC / Disk Operation / Save Game.

Requirements
  * 1 MB RAM or more (patch code, bank and file cache live above 512 KB; a 512 KB machine runs the unpatched game).
  * The disk is in 11-sector format with 82 tracks: write it with a tool that supports it (Fastcopy, MSA-style
    writers, Gotek/HxC: use the .st as is) and a drive that reaches track 81.  The image has no interleave: have the
    writer apply a sector skew, otherwise the game loads slowly.
  * Joystick in port 1 (cursor keys + fire on emulators).

Tested on Hatari (cold boots to the 3D view, sky/palette/dashboard/buffering as in the table, keys): one-disk set on STE (TOS 1.62) at
1 MB and 2 MB, ST (TOS 1.04) at 1 MB, Falcon (TOS 4.04) at 4 MB. The TT was tested with the hard-disk build only. Not tested on real hardware.
Even mouse pointer: cold boots to the 3D view with the item table opened and clicked with the pointer, one-disk set on the STE, TT and Falcon
(the ST row: same code, tested with the hard-disk build).
